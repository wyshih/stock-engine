## 1. 系統概覽

### 1.1 系統定位
本系統為台股輔助決策工具，提供預測建議供使用者參考，最終買賣決策由使用者自行判斷。系統採寧缺勿濫原則，沒有足夠信心的標的不推薦。

### 1.2 目標市場
- 台股上市股票（TWSE）
- 台股上櫃股票（TPEX）
- 合計約 1800 檔股票

### 1.3 股票類型分類

| 類型 | 說明 | 納入 | 備註 |
|------|------|------|------|
| 一般股票（普通股） | 一般上市上櫃公司 | ✅ | 主力，約1400檔 |
| ETF | 指數股票型基金 | ✅ | 獨立模型，約200檔 |
| 特別股 | 固定股息，優先清算 | ❌ | 資料太少 |
| REITs | 不動產投資信託 | ❌ | 台灣檔數太少 |
| 存託憑證（TDR） | 外國公司在台掛牌 | ❌ | 流動性差 |
| 權證 | 衍生品 | ❌ | 邏輯完全不同 |

> ETF 籌碼面特徵幾乎無效，需獨立訓練，不與一般股票混在一起

### 1.3 核心功能
- **盤後推薦名單**：每天收盤後產生當日推薦買入名單
- **多週期共振判斷**：短線、中線、長線同時看漲才推薦
- **盤中即時監控**：手動刷新指定股票，確認趨勢是否延續
- **回測驗證系統**：驗證模型歷史表現，自動找最佳參數
- **模型成效監控**：追蹤每個子模型的準確率，即時警示

### 1.4 使用者
- 少數人共用，需要帳號登入（Email + 密碼）
- 登入後保持永久登入狀態
- 所有使用者共用同一套預測結果

### 1.5 開發機器

| 規格 | 說明 |
|------|------|
| 型號 | MacBook Air M5 |
| 記憶體 | 24GB 統一記憶體 |
| 儲存空間 | 512GB SSD |
| 核心數 | 10核心 CPU + 10核心 GPU |
| 作業系統 | macOS |

## 2. 整體架構

### 2.1 系統架構

系統由四個主要層次組成：
- **資料層**：負責資料搜集、清洗、儲存
- **特徵層**：負責技術指標計算、特徵工程
- **模型層**：負責預測模型訓練和推論
- **介面層**：負責前端呈現和使用者互動

| 層次 | 元件 | 技術 |
|------|------|------|
| 資料層 | CSV 檔案儲存 | GitHub Repository |
| 資料層 | 每日自動更新 | GitHub Actions |

## 3. 資料搜集系統

### 3.1 資料來源

| 資料類型 | 來源 | 更新頻率 | 備註 |
|---------|------|---------|------|
| 日線價格量 | Yahoo Finance (yfinance) | 每日 | 存原始+還原兩份 |
| 三大法人買賣超 | FinMind（歷史）/ TWSE+TPEX（每日） | 每日 | t日資料只能預測t+1 |
| 融資融券 | FinMind（歷史）/ TWSE+TPEX（每日） | 每日 | t日資料只能預測t+1 |
| 外資持股比例 | FinMind | 每日 | 看增減趨勢 |
| 月營收 | FinMind / MOPS | 每月 | 記錄實際公布日期 |
| 基本面（PER/PBR/殖利率） | FinMind | 每日 | 日頻更新 |
| 異常股票狀態 | TWSE / TPEX 每日公布 | 每日 | 全額交割/處置/警示 |
| 大盤加權指數（^TWII） | Yahoo Finance | 每日 | 大盤模型用 |
| 美股S&P500（^GSPC） | Yahoo Finance | 每日 | 大盤模型用 |
| VIX恐慌指數（^VIX） | Yahoo Finance | 每日 | 大盤模型用 |
| 台幣匯率（TWD=X） | Yahoo Finance | 每日 | 大盤模型用 |

### 3.2 歷史資料初始化
- 使用 FinMind 免費版（登入後 1500 次/小時）
- 逐檔拉取近三年完整資料（2023~2025）
- 週末開著跑，約需 4 小時完成
- 一次性作業，之後只需每日增量更新

### 3.3 每日更新流程
- GitHub Actions 每天下午 5:30 自動觸發（週一至週五）
- 從 TWSE/TPEX OpenAPI 一次請求拿全市場當天資料
- 判斷是否為假日（資料為空則跳過）
- Append 新資料到對應 CSV 檔案
- Commit + Push 回 GitHub Repository
- 每天新增資料量約 180KB

### 3.4 資料驗證機制
- 價格驗證：漲跌幅是否在合理範圍（台股±10%）
- 欄位驗證：是否有缺漏欄位（NULL）
- 成交量驗證：是否為 0 或異常大
- 籌碼驗證：買賣超是否合理、持股比例是否在 0~100%
- 營收驗證：是否為負數或異常值
- 驗證失敗：輕微異常填 NaN，嚴重異常跳過並記錄 log

### 3.5 資料時間對齊原則
- **籌碼資料**：t 日籌碼只能用於預測 t+1 日（避免資料洩漏）
- **月營收**：只能用已公布的最新一期（用實際公布日期對齊）
- **前波高低點**：延遲 N 天確認（前後各 N 天都比它低/高才確認）

## 5. 特徵工程

### 5.1 特徵設計原則
- 所有價格相關特徵使用相對值（%、比值），不用絕對價格
- 不同股價的股票才能跨股票比較學習
- 持續天數特徵使用 log 轉換或分位數標準化
- 週線和月線從日線動態 resample 產生
- 前波高低點延遲 N 天確認，避免資料洩漏

### 5.2 時間週期對應

| 週期 | 模型 | Lookback | 確認天數N |
|------|------|---------|---------|
| 日線（T1/T4/T5/T6） | 短線模型 | 過去20~60天日線 | N=5 |
| 週線（T2） | 中線模型 | 過去20~60週週線 | N=20 |
| 月線（T3） | 長線模型 | 過去12~36個月月線 | N=60 |

### 5.3 技術指標特徵

#### 均線系列
- MA5/10/20/60/120/240（日線）
- 收盤價距各均線距離%（dist_ma5, dist_ma20...）
- 均線壓力支撐：是否在均線 ±1%/3%/5% 範圍內
- 是否在均線上方（above_ma5, above_ma20...）
- 三/四/五線多排狀態及持續天數（is_3ma_bull, days_3ma_bull...）
- 三/四線空排狀態及持續天數

#### KD 指標
- K 值、D 值
- 黃金/死亡交叉及持續天數
- 超買（K>80）、超賣（K<20）
- 從超賣反彈訊號

#### MACD 指標
- DIF 值、MACD 值、Histogram 柱狀圖
- 黃金/死亡交叉及持續天數
- Histogram 擴大/縮小及持續天數

#### 布林通道
- 上軌、中軌、下軌
- 價格在通道相對位置（0=下軌，1=上軌）
- 突破上軌、跌破下軌
- 通道寬度、通道擴大持續天數

#### RSI
- 14 日 RSI
- 超買（>70）、超賣（<30）
- 從超賣反彈、持續在 50 以上天數

#### 價格動能
- 5/10/20/60 天報酬率
- 動能是否加速
- 距 60 天高低點%、是否創 60 天新高

#### 波動度
- ATR14（平均真實波幅）
- 20 日滾動標準差

#### 量價關係
- OBV（成交量累積指標）
- 量比（今天/5日均量）
- 放量突破（量比>2且上漲）

### 5.4 前波高低點特徵
- 前三個前波高點：距離%、距今天數
- 前三個前波低點：距離%、距今天數
- 是否高點越來越高（is_higher_highs）
- 是否低點越來越高（is_higher_lows）
- 是否高點越來越低（is_lower_highs）
- 是否低點越來越低（is_lower_lows）
- **確認方式**：前後各 N 天都比它低/高才確認（不使用未來資料）

### 5.5 大量高低點特徵
- 大量定義：成交量 > 2 倍 20 日均量
- 前三個大量高點：距離%、距今天數
- 前三個大量低點：距離%、距今天數
- 是否突破最近大量高點（is_above_vol_high1）
- 是否跌破最近大量低點（is_below_vol_low1）
- 剛突破大量高點（is_vol_high_breakout）

### 5.6 趨勢線特徵
- 連接前波低點做線性回歸 = 支撐趨勢線
- 連接前波高點做線性回歸 = 壓力趨勢線
- 每天重新計算，R² 品質指標
- 距支撐/壓力線%、斜率
- 是否接近（±3%）、突破、跌破
- 支撐線與壓力線是否收斂（三角收斂）

### 5.7 籌碼特徵
- 外資/投信/自營商每日買賣超
- 三大法人合計買賣超
- 外資連續買超天數
- 投信近 5/10 天累計買賣超
- 外資/投信/自營商持股比例及變化趨勢
- 融資買進/賣出/餘額及變化率
- 融券買進/賣出/餘額及變化率

### 5.8 基本面與營收特徵
- PER、PBR、殖利率
- PER/PBR 歷史分位數
- 最新月營收 YoY、MoM
- 累計營收 YoY
- 連續幾個月 YoY 為正
- 營收是否加速成長
- 近三期營收趨勢斜率

### 5.9 異常狀態與流動性特徵
- is_full_cash：是否全額交割股
- is_disposed：是否處置中
- is_warning：是否警示股
- 日均量（近20天）
- 日均成交金額

## 6. 預測模型系統

### 6.1 整體模型架構
採用兩層 Stacking 集成學習架構：

**第一層（子模型）**：每個子模型有多個實作版本並存——
- 傳統 ML 版：RandomForest（RF）、GradientBoosting（GBT）、LogisticRegression（LR）
- 深度學習版：LSTM（序列模型）或 1D-CNN（圖形模型），視子模型性質選擇

**第二層（Meta 模型）**：接收第一層所有版本的輸出機率作為特徵，做最終整合預測。
Meta 的輸入包含：`T1_RF_prob, T1_GBT_prob, T1_LR_prob, T1_LSTM_prob, T2_RF_prob, ...`

深度學習版本與傳統 ML 版本**並存而非取代**，兩者都送進 Meta，由 Meta 自動學習各版本的權重。

### 6.2 傳統 ML 演算法設定
- **RandomForest**：`class_weight='balanced'`，n_jobs=-1
- **GradientBoosting**：GBDT，無 class_weight，透過 sample_weight 處理不平衡
- **LogisticRegression**：`class_weight='balanced'`，saga solver + StandardScaler
- **超參數搜索**：RandomizedSearchCV + TimeSeriesSplit（cv=3）
- **機率校正**：Isotonic Regression（`CalibratedClassifierCV(FrozenEstimator(clf))`）
- **評估指標**：F1-score、AUC-ROC、Precision-Recall 曲線

### 6.2.1 深度學習模型規格

> 深度學習版本與傳統 ML 並存，均輸出 [0,1] 機率值送入 Meta。

| 子模型 | DL 架構 | 輸入格式 | 序列長度 | 說明 |
|--------|---------|---------|---------|------|
| T1/C1/C2 | **LSTM** | 過去 N 天各日線特徵序列 | N=20 | 捕捉短線動能的時序依賴 |
| T2 | **LSTM** | 過去 N 天各日線特徵序列 | N=60 | 中線趨勢的序列型態 |
| T3 | **LSTM** | 過去 N 天各日線特徵序列 | N=120 | 長線趨勢的長程依賴 |
| T4/T5/T6 | **1D-CNN** | 過去 N 天各日線特徵序列 | N=20 | 局部圖形型態辨識 |
| Meta | **MLP** | 所有子模型 × 所有演算法的輸出機率向量 | — | 非線性整合各子模型信號 |

**輸入設計（序列模型）**：
- 對每個預測日 t，建構序列 `[features[t-N+1], ..., features[t]]`，shape = `(N, num_features)`
- 特徵使用各子模型對應的 feature group（與傳統 ML 相同欄位）
- 序列中的 NaN 以前向填補（同 tabular 版），保留時間順序

**LSTM 架構**：
```
Input (N, F) → LSTM(128) → Dropout(0.2) → LSTM(64) → Dropout(0.2) → Linear(1) → Sigmoid
```

**1D-CNN 架構**：
```
Input (N, F) → Conv1d(64, k=3) → ReLU → Conv1d(128, k=3) → ReLU → AdaptiveMaxPool → Linear(1) → Sigmoid
```

**訓練設定**：
- Loss：`BCEWithLogitsLoss(pos_weight=…)`（處理不平衡）
- Optimizer：Adam，lr=1e-3，weight decay=1e-4
- Scheduler：ReduceLROnPlateau
- Early stopping：val loss 不改善 10 epoch 停止
- 框架：PyTorch
- 機率校正：同傳統 ML，在 val 上做 Isotonic Regression

### 6.3 子模型清單

| 模型ID | 名稱 | 預測目標 | 使用特徵 | Ground Truth |
|--------|------|---------|---------|-------------|
| T1 | 日線短線動能 | 未來5天漲幅≥7% | 日線技術 + 週線/月線（趨勢背景）+ 籌碼 + Swing + 基本面/營收 | t+1~t+5還原收盤價漲幅≥7%（固定門檻） |
| T2 | 週線中線動能 | 未來20天漲幅達標 | 週線技術 + 日線（入場時機）+ 基本面 + 營收 | t+1~t+20還原收盤價漲幅 |
| T3 | 月線長線動能 | 未來60天漲幅達標 | 月線技術 + 週線（中期確認）+ 基本面 + 營收 | t+1~t+60還原收盤價漲幅 |
| T4 | 日線低點反彈（寬鬆） | 任何趨勢下低點反彈 | 日線技術 + Swing + 週線/月線（趨勢背景） | 局部低點後5天漲幅>5% |
| T5 | 日線低點反彈（嚴格） | 上升/平盤趨勢下低點反彈 | 日線技術 + Swing + 週線/月線（趨勢背景） | 上升/平盤趨勢局部低點後5天漲幅>5% |
| T6 | 日線高點反轉 | 高點反轉下跌 | 日線技術 + Swing + 週線/月線（趨勢背景） | 局部高點後5天跌幅>5% |
| C1 | 籌碼強度 | 未來10天法人是否持續買入 | 籌碼特徵 | 未來10天三大法人累計買超為正 |
| C2 | 三大法人動向 | 各法人未來5天是否淨買超 | 籌碼特徵 | 未來5天外資買賣超累計為正 |
| C3 | 外資持股趨勢 | 外資持股比例未來20天是否上升 | 外資持股 + 基本面 | 20天後持股比例高於現在 |
| F1 | 營收動能 | 下期月營收是否加速成長 | 月營收歷史 + 基本面 | 下期YoY高於本期YoY |
| Meta | 綜合判斷 | 是否為好的買入時機 | 所有子模型輸出機率（10個） | 短中長線全部達標 |

> **多時間框架特徵設計原則**：較短線模型（T1/T4/T5/T6）可使用較長時間框架特徵作為趨勢背景。
> 週線特徵在同一週內所有交易日使用相同值；月線特徵在同一月份內所有交易日使用相同值。
> 此 forward-fill 由特徵工程層負責，dataset 層做 date-index join 即可，不存在 NaN 或資料洩漏問題。

### 6.4 大盤預測模型

| 模型ID | 名稱 | 預測目標 | 使用特徵 | Ground Truth |
|--------|------|---------|---------|-------------|
| M1 | 大盤短線方向 | 大盤未來5天看多或看空 | 大盤技術指標 + 整體籌碼 + 總經 | 大盤5天後漲跌方向 |
| M2 | 大盤中線方向 | 大盤未來20天看多或看空 | 大盤週線技術指標 + 總經 | 大盤20天後漲跌方向 |
| M3 | 大盤長線方向 | 大盤未來60天看多或看空 | 大盤月線技術指標 + 總經 | 大盤60天後漲跌方向 |

**大盤模型特徵：**
- 大盤技術指標：加權指數日/週/月線均線、KD、MACD、RSI
- 整體市場籌碼：全市場三大法人買賣超、整體融資融券水位
- 總經指標：美股S&P500、VIX恐慌指數、台幣匯率、漲跌家數比
- 全部來自 Yahoo Finance（^TWII、^GSPC、^VIX、TWD=X）

**大盤模型對推薦名單的影響：**

| 大盤狀況 | 對推薦的影響 |
|---------|------------|
| M1/M2/M3 都看多 | 推薦名單正常顯示 |
| M1看空但M2/M3看多 | 短線保守，加上警示 |
| M1/M2都看空 | 整體警示，提高買入門檻 |
| M1/M2/M3都看空 | 暫停推薦或強烈警示 |

### 6.5 Ground Truth 定義
- **買入價**：t+1 日還原收盤價（t 日看到訊號，t+1 日才能買）
- **賣出價**：t+N 日還原收盤價
- **漲幅** = (t+N還原收盤 - t+1還原收盤) / t+1還原收盤

**各模型漲幅門檻：**

| 模型 | 門檻 | 定義方式 | 說明 |
|------|------|---------|------|
| T1 | **7%（固定）** | 硬編碼 | 5天強勢突破；正樣本率約5~10% |
| T2 | **20%（固定）** | 硬編碼 | 1個月內強勢波段；寧缺勿濫 |
| T3 | **50%（固定）** | 硬編碼 | 3個月趨勢行情；只捕捉真正大波段 |
| T4/T5 | **5%（固定）** | 硬編碼 | 低點反彈確認門檻 |
| T6 | **-5%（固定）** | 硬編碼 | 高點下跌確認門檻（跌幅） |

- **T4/T5/T6**：額外條件為局部高/低點（swing point）確認，訓練時可用完整歷史標記，預測時模型直接輸出機率

### 6.6 Meta 模型輸出

| 輸出 | 說明 |
|------|------|
| 綜合評級 | 強烈買入 / 買入 / 觀望 / 避開（門檻由回測決定） |
| 多週期共識 | 短線/中線/長線各自看漲或看空 |
| 買入機率 | 0~1 的機率值（Isotonic 校正後） |

### 6.7 Train/Test 切割

| 資料集 | 時間範圍 | 用途 |
|--------|---------|------|
| 子模型 Train | 2023~2024 | 訓練子模型 |
| 子模型 Validation | 2025上半年 | 門檻搜索、超參數調整 |
| 子模型 Test | 2025下半年 | 最終評估 |
| Meta模型 Train | 子模型對2025上半年的預測結果 | 訓練Meta模型 |
| Meta模型 Test | 2025下半年 | 最終評估 |

### 6.8 模型更新策略
- 不定期強制重訓，由準確率監控觸發
- 透過 prediction_log 追蹤推薦準確率
- 準確率明顯下降才觸發重訓
- 重訓時使用最新三年資料
- 每次重訓記錄在 model_versions，保留舊版本備用

## 7. 每日自動化流程

### 7.1 GitHub Actions 排程
- 時間：每天下午 5:30（台灣時間，UTC 09:30）
- 條件：只在週一到週五執行
- 假日判斷：抓到的資料如果是空的就自動跳過

### 7.2 每日更新步驟
1. 從 TWSE/TPEX 抓當天所有股票資料
2. 資料驗證（價格/籌碼/異常值）
3. Append 新資料到 CSV 檔案
4. 更新異常股票狀態（全額交割/處置/警示）
5. Commit + Push 到 GitHub
6. 回填 prediction_log 中已到期的預測結果

### 7.3 錯誤處理
- 每檔股票用 try/catch 包住，失敗記錄 log 並跳過
- 整體流程失敗記錄到 GitHub Actions 執行記錄
- 失敗的股票隔天重新處理

### 7.4 預測觸發
- 使用者開網頁才觸發預測（非自動）
- 10 核心平行計算全部 1800 檔
- 約需 30~60 秒，顯示 Loading 進度畫面
- 結果快取在記憶體，同天第二個使用者直接讀取
- 隔天快取自動清除

## 9. 回測系統

### 9.1 評估層次

#### 第一層：模型準確度
- Precision（預測漲的，真的漲的比例）
- Recall（真正漲的，被抓到的比例）
- F1-score（綜合指標）
- AUC-ROC、Precision-Recall 曲線
- Directional Accuracy（方向準確率）

#### 第二層：實際獲利
- 每筆交易報酬率
- 平均報酬率
- 勝率（賺錢次數/總次數）
- 最大單筆虧損
- 累計總報酬及資產曲線

### 9.2 交易模擬規則
- 買入：t+1 日還原收盤價
- 不納入交易成本（手續費/交易稅）
- 賣出條件：固定持有 N 天到期 或 停損（哪個先到就賣）
- 倖存者偏差：未納入已下市股票，在介面上標注說明

### 9.3 自動門檻測試
- 只在 Validation 資料（2025上半年）上測試
- Test 資料用 Validation 找到的最佳門檻驗證

| 參數 | 測試範圍 | 顆粒度 | 組合數 |
|------|---------|--------|--------|
| 買入機率門檻 | 50% ~ 95% | 每隔1% | 45個值 |
| 停損門檻 | -3% ~ -20% | 每隔0.5% | 34個值 |
| 持有天數 | 1 ~ 30天 | 每天 | 30個值 |
| 總組合數 | — | — | 約45,900種 |

- M5 10 核心平行處理，加速門檻搜索
- 結果以熱力圖顯示最佳組合
- 自動標出最佳門檻組合

## 12. 重要設計原則

### 12.1 資料洩漏防護
- 籌碼資料：t 日籌碼只能用於預測 t+1 日
- 月營收：只能用已公布的最新一期，以公布日期對齊
- 前波高低點：延遲 N 天確認，不使用未來資料
- 門檻測試：只在 Validation 資料上做，Test 資料只用於最終驗證
- 子模型與 Meta 模型必須使用不同年度資料訓練

### 12.2 模型品質保證
- 訓練時使用 class_weight='balanced' 處理資料不平衡
- 輸出機率用 Isotonic Regression 校正
- 評估指標使用 F1-score、AUC-ROC（不用Accuracy）
- Cross Validation 使用 TimeSeriesSplit（不用隨機切割）
- 超參數搜索使用 Random Search

### 12.3 系統可靠性
- 每天資料抓取後自動驗證合理性
- 平行計算加入錯誤隔離，單檔失敗不影響整體
- 適當的 Log 記錄，方便追蹤問題
- 模型版本控制，可隨時切換回舊版本

### 12.4 回測注意事項
- 未納入已下市股票（倖存者偏差），在介面上標注說明
- 不納入交易成本，實際結果會略低於回測
- 買入價格使用 t+1 日還原收盤價，符合實際交易情境

### 14.4 Step 1：建立測試框架
